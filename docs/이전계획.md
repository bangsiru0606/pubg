## 1. 기존 프로젝트 분석 요약

### 1.1 craft_on (살릴 대상)

- Unity 6000.3.13f1, URP 2D.
- **씬을 손으로 배치하지 않고 `Assets/Editor/StoryBuilder.cs`가 코드로 생성**한다. 층·방·NPC·조사 지점의 X 좌표가 전부 코드 상수라 그대로 맵 데이터로 옮길 수 있다.
- 작동하던 시스템:
  - X축 이동 (`PlayerController`), 걷기/대기 프레임 애니메이션 + 좌우 반전 (`PlayerVisual`, `NpcVisual`)
  - 근접 시 상호작용 프롬프트 (`InteractionDetector`, `InteractionPromptUI`) — NPC "대화하기", 오브젝트 "조사하기", 문/계단 "{장소} 들어가기/올라가기"
  - 구역 전환 + 페이드 (`AreaManager`, `AreaTransition`, `DoorInteractable`, `CutsceneFadeUI`)
  - 자동 트리거 구역 (`AutoTriggerZone`) — 백선우 앞을 지나가면 대화 시작
  - 대화 노드 + 선택지 대화 (`DialogueRunner`, `DialogueChoiceController`, `DialogueUI`) — 화자 초상 표정 포함
  - Tab 단서 수첩 (`ClueJournalUI`, `ClueDetailView`)
  - 마우스 근접 조사 화면 (`MouseCloseupUI`, `DeskExamineInteractable`) — 호버 하이라이트, 클릭 시 확대 팝업
  - 이름 입력 팝업, 튜토리얼 힌트, 병원 도착 컷신
- 콘텐츠는 **보정 전 기획서** 기준(찻잔·독살, 단서 37개, 질문 3개, 엔딩 3종)이라 대부분 폐기 대상.
- 아트 현황: 사무실(씬 1)은 실제 아트로 완성. **병원 9개 구역은 전부 절차 생성 placeholder(색 사각형)**.

### 1.2 codex (참고)

- 보정판 기준으로 단서 E01~E16을 유형까지 정리한 `evidence_catalog.json` → `docs/legacy/codex_evidence_catalog.json`에 보관. 그대로 출발 데이터로 쓴다.
- `GameState`, 저장·백업, 판정 테스트 구조도 보정판 10장과 일치 → 설계만 참고.
- 나머지(단일 22KB UI 컨트롤러, 화면 크기 페인팅 배경, 여성 탐정 초상)는 쓰지 않는다.

### 1.3 비율 문제의 원인

1. **craft_on이 에셋마다 PPU를 따로 역산했다.** 플레이어 180, 바닥 170, 창문 약 300, 책상 482. 그래서 화면에서 "픽셀 한 칸"의 크기가 에셋마다 최대 3배 다르다.
2. **AI 생성 이미지는 진짜 픽셀 격자가 없다.** 같은 그림 안에서도 덩어리 크기가 3~10px로 섞여 있다.
3. codex는 배경을 화면 크기 그림으로 깔고 캐릭터를 UI로 얹어서 둘 사이의 기준이 없었다.

→ 해결: **논리 해상도 하나를 고정하고, 모든 탐색 에셋을 그 격자에 맞게 다시 줄인다.** (2장)

## 2. 해상도·에셋 규격 (1단계에서 시각 검증 후 확정)

### 2.1 제안 기준

| 항목 | 값 |
|---|---|
| 논리 해상도 | **480 × 270** (16:9). 화면에는 정수 배율(×2 960×540, ×3 1440×810, ×4 1920×1080)로만 확대, 남는 영역은 레터박스 |
| 렌더링 | Phaser `pixelArt: true`, `roundPixels: true`, CSS `image-rendering: pixelated` |
| 캐릭터 높이 | 약 **90px** (화면 높이의 1/3, craft_on의 카메라 구성과 동일한 체감) |
| 배경 | 층 복도는 높이 270px, 가로는 길이에 맞춰 자유 |
| 피벗 | 캐릭터·문·가구는 **하단 중앙**. 바닥선 y 하나를 모든 구역이 공유 |
| 화면 구도 | 바닥선 **y=158 고정**. 바닥선 아래 영역(약 112px)은 대화창·프롬프트 UI 자리로 쓴다 |
| 클로즈업·초상·컷신 | 픽셀 격자 대상 아님. HTML 오버레이에서 원본 해상도 그대로, 부드럽게 표시 |

### 2.2 에셋 정규화 파이프라인

`tools/normalize-assets.(ts|py)` 하나로 처리하고, 원본은 `art/source/`에 보존, 결과만 `public/assets/`에 둔다.

1. 원본에서 투명 여백 자르기
2. 목표 높이(예: 캐릭터 90px, 창문 60px)로 **축소** — 박스/영역 평균으로 줄인 뒤
3. 팔레트 양자화(32~48색)로 덩어리를 다시 선명하게
4. 바닥 접지선 정렬 확인
5. `assets.json`에 크기·피벗·용도 기록

목표 높이 표는 `art/asset-spec.json`에 데이터로 둔다. 새 에셋을 만들 때도 이 표에 맞춰 생성한다.

### 2.3 새 에셋 그림체 규칙

- 탐색 스프라이트: craft_on `Art/Player`, `Art/ParkEunho`와 같은 외곽선 굵기·채도·명암 단계. 생성 후 반드시 2.2 파이프라인을 거친다.
- 반실사 에셋: craft_on `Art/Portraits`, `Resources/Art/Office/*_detail.png`, `Cutscenes/hospital_intro.png`의 붓터치·색감에 맞춘다.
- 병원 톤: 낮은 채도, 청록·회색. 교단 상징에만 탁한 주황. 고어 금지.
- 이미지에 글자를 굽지 않는다(문서 내용은 HTML로 표시). 예외: 이미 있는 신문 헤드라인.

### 4.2 맵 배치 이전

`StoryBuilder.cs`의 `Build*()` 함수에서 구역별 minX/maxX와 오브젝트 X를 뽑아 `src/data/map.json`으로 옮긴다. 그 뒤 **보정판 8장 기준으로 수정**한다.

### 6.2 "더블클릭 실행" 기술 규칙

가이드의 HTML/JS 항목은 "빌드 없이 폴더째 압축, `./img/a.png` 같은 상대경로"를 전제로 한다. 우리는 Vite로 빌드하지만, **빌드 결과물이 그 조건을 만족**하면 된다. `file://`로 열면 브라우저가 막는 것들을 처음부터 피한다.

| 막히는 것 | 대응 |
|---|---|
| 외부 JS 파일을 `<script type="module" src>`로 로드 | JS를 `index.html` 안에 인라인 (`vite-plugin-singlefile`). Vite `base: './'` |
| `fetch()`/XHR로 JSON 읽기 | 데이터는 TS `import`로 번들에 포함 |
| Phaser 로더의 XHR 이미지 로드 | Phaser 설정 `loader.imageLoadType: 'HTMLImageElement'` → `<img>`로 로드되어 `file://`에서도 동작. 이미지는 `./assets/...` 상대경로 파일로 둔다 |
| `@font-face` 폰트 파일 로드 (브라우저별로 차단) | 폰트는 CSS에 base64로 넣거나 시스템 한글 폰트(맑은 고딕) 사용 |
| 오디오 XHR 로드 | 사운드를 쓰면 `<audio>` 요소로 로드 |
| `localStorage` | `file://`에서도 대체로 되지만 try/catch 필수, 실패 시 세이브 없이 진행 |

배포 폴더 구조:


## 8. 판정 규칙 확정 (2단계 검토 결과)

기획서에서 모호하거나 충돌하던 판정 규칙을 아래처럼 확정한다. 코드 위치: `src/core/deduction.ts`, `src/core/ending.ts`, `src/data/endings.json`.

1. **질문 해결 조건**: 정답 가설 + 근거 충족(정답 가설의 맞는 근거 2개, 유형은 묻지 않는다 — 5차 피드백 11.18 에서 "서로 다른 유형 2개" 조건을 없앴다) + 합계 2점 이상.
2. **반박 근거**: UI에서는 반박 슬롯이 비어 있으면 결론을 저장(제출)할 수 없다. 반박이 맞았는지는 해결 여부가 아니라 점수·추리 등급에만 반영한다. (`canSaveConclusion`, `isRebuttalFilled`)
3. **보고 대상**(박은호만 / 외부 수사기관 포함)은 엔딩 A 판정과 결과 문장 선택에만 쓴다.
4. **질문 C 반박 근거**는 `E06_torn_sleeve`.
5. 검증 퍼즐이 없는 단서(E01, E04, E08, E09, E16)는 획득 즉시 검증 상태로 둔다.
6. **EndingResolver 판정 순서** (위에서부터 처음 맞는 것):
   1. A: 4개 모두 해결 && 증거 보존 && 외부 수사기관 포함
   2. B: A·B만 해결(C·D 둘 다 미해결). 보존·보고와 무관
   3. D: 미해결 2개 이상 || 질문 A 미해결
   4. C: 미해결 1개 이하 && (증거 미보존 || 외부 보고 안 함)
   5. B: 나머지(미해결 1개 && 증거 보존 && 외부 보고)

   해결 4개 × 보존 × 보고 = 64조합 결과는 A 1 / B 7 / C 12 / D 44 (`tests/ending.test.ts`가 전체 표를 검사).
   **기획서 10.4 의사코드와 순서가 다른 이유**: 10.4는 A→B→C→D 순서와 "그 외는 D"로 쓰였지만, 7장의 엔딩 D 조건("2개 이상 오답")이 C보다 먼저 적용되어야 해결 질문이 1~2개뿐인 플레이가 엔딩 C("빈 병원")로 새지 않는다. 또한 10.4에 없는 "A·B만 해결" B 조건(7장)을 두 번째에 둬 C와 겹치지 않게 했다.
7. **엔딩 결과 본문**: 엔딩 카드(제목·카드 문구)는 4종 그대로. 결과 본문은 정하늘 / 조직 / 박은호 세 줄로 나누고, 질문별 해결 여부와 증거 보존·보고 여부로 문장을 고른다(`endings.json`의 `lines`). 문장은 기획서 7장 문장을 재사용하며, 새로 쓴 문장은 `source: "new"`로 표시해 검토한다.
8. **4.4 근거 충돌 중립 경고**는 보류가 아니라 3단계 사건 수첩에서 구현한다. 단서 데이터의 `sourceCharacterId`·`timestamp`로 판정한다(같은 인물이 만든 서로 다른 자료의 시각 범위가 겹치면 경고, 내용 판단은 하지 않음). `findConflicts`.

## 10. 7단계 결정 (플레이테스트 수정 · 편의 도구 · 에셋 파이프라인 · UI 디자인)

- **이름**: 새 게임에서 입력(1~8자, 기본 "한지수" = `characters.json` 의 han_jisu 한 곳). 데이터에는 `{player}` 토큰만 쓰고 화면 단계(`esc`)에서 치환한다. validate 가 대사·엔딩·단서·퍼즐 데이터의 하드코딩을 막는다.
- **오프닝**: `map.json` 의 `opening` 에 단계(대화·카메라·등장·걷기·퇴장·힌트)를 데이터로 정의. 노크 두 줄은 `source: "craft_on"`.
- **구역 전환은 Enter 로만**: 대상이 없을 때 눌린 Enter 가 쌓여 계단 앞에서 자동 이동하던 버그를 고쳤다. 자동 전환이 필요하면 `auto: true` 를 지도에 명시한다(현재 없음). 도착 위치(spawnX)는 도착 구역의 어떤 전환 지점 범위(45px) 안에도 두지 않는다.
- **에셋 파이프라인**: `art/asset-spec.json` 의 `chromaKey`(#00FF00 제거, 가장자리 번짐 제거), 시퀀스 `facing`. `npx tsx tools/import-generated.ts` 가 `art/source/generated/manifest.json` 으로 spec 초안을 만든다(`--apply` 로 병합). 지도 데이터의 `bg`(wall·floor·topband 키)·소품 `tex` 키가 있고 텍스처가 로드되어 있으면 그림, 없으면 색 사각형.
- **UI 시각 언어**: 어두운 원목 · 바랜 종이 · 놋쇠. 단서 유형은 모양(■ 물증 / ≡ 기록 / “ 증언 / ◇ 맥락), 진술은 기호(“ 미확인 / ≠ 모순 / ✎ 수정)로도 구분한다.
- **개발 전용**: `npm run dev` 의 F9 디버그 메뉴(씬 1~7 점프, 저장 초기화, 상태 보기). 제출 빌드에는 없다(`import.meta.env.DEV` 분기, test:release 검사). 씬 점프 상태는 `src/explore/playthrough.ts` 가 만들고 코어 테스트와 공유한다.
- **외곽선 보정**: asset-spec 의 `outline: true` 항목(생성 인물·소품 기본값)은 정규화 때 투명과 맞닿은 불투명 가장자리 1줄을 한지수 스프라이트의 외곽선 색으로 칠한다(실루엣 불변). 숨쉬기 프레임은 보정 후 idle_0 에서 만든다.
- **배치 3~5 미리 연결**: 지도 데이터의 `bg`·`art`·`objects`·`props.tex` 와 characters.json 의 `expressions` 를 지정해 두었다. 파일이 없으면 색 사각형·마름모·회색 실루엣이고, `npm run validate` 는 아직 없는 텍스처·초상을 경고로만 보여 준다. 소품 높이 초안은 `tools/import-generated.ts` 의 `PROP_HEIGHT`(수치가 규격에 없는 것은 초안 값).

## 11. 기획서와 다르게 처리한 부분

기획서(`docs/기획서_보정판.md`)와 다르게 만든 것을 여기에 모은다. 플레이 테스트에서 "퍼즐이 무작위 배치와 반복 확인으로 풀린다"는 문제가 나와 퍼즐 판정을 단서와 연결하는 방식으로 바꾸면서 생겼다.

### 11.1 E05(원장실 출입 기록) 획득 위치: 3층 간호사실 → 2층 복도 방송표
- 기획서 11장은 E05 를 3층 간호사실에서 얻는다고 하고, 같은 문서는 P02 를 2층에서 풀어 `flag_night_timeline` 을 세운 뒤에야 3층에 올라간다고 한다. 따라서 P02 를 풀 때는 E05 가 없다.
- P02 의 22:41 칸("원장실 문 개방")은 E05 의 "22:41 / 청소용 마스터키 사용"이 유일한 근거라서, 근거 카드를 붙이게 하려면 E05 가 P02 보다 먼저 있어야 한다.
- 그래서 E05 를 2층 복도 방송표 조사(`mono_broadcast`)에서 얻게 했다(방송표 아래 단말기에 꽂힌 출입 기록 출력지). 간호사실 재고표에는 E09 만 남았다. E05 의 검증(P02 해결 시), 단서 ID, 본문은 그대로다.

### 11.2 P03 선택지 5개 → 7개
- 기획서의 선택지는 의미 변경 3개와 방해 2개(맞춤법, 문장 위치)였다. 선택지가 5개면 무작위 제출로도 쉽게 맞는다(수정 전 17.95%, 오답 5회 이내).
- 사소한 서식 변경 2개("22:52 → 22시 52분" 시각 표기, "※ → *" 머리 기호)를 방해 선택지로 더하고, 최종 기록 패널에 그 변경이 실제로 보이게 했다. 정답 3개와 정답 배치는 그대로다.

### 11.3 퍼즐 근거 카드 규칙 (4.6 공통 난이도 규칙에 더한 것) — 11.12 에서 폐기
- 각 정답 칸에 토큰을 놓으면 그 칸에 근거 카드(단서·진술)를 붙여야 한다. 토큰과 근거가 모두 맞아야 정답이다. 허용 근거는 `puzzles.json` 의 `evidenceLinks`, 판정은 `src/core/puzzle.ts` 에서만 한다. P05 의 "신원 확정에 연결한 자료" 칸은 칸 자체가 근거 선택이라 근거 칸이 없다.
- 근거 후보는 가진 단서·진술 전부이고(정답 근거만 추리지 않는다), 맥락 단서(E01)는 고를 수는 있어도 근거로 인정되지 않는다.
- 근거를 붙이지 않은 칸이 있으면 오답이 아니라 `incomplete` 다. 오답 횟수와 힌트 단계는 오르지 않고, 화면은 "근거를 붙이지 않은 칸이 있다." 하나만 알려 주며 빈 근거 칸을 강조한다. 근거가 붙어 있는데 틀리면 오답이다.
- 오답이면 충돌 문장은 하나다: 근거 문제가 먼저, 그다음 토큰 충돌이고, 어느 자료와 맞지 않는지 자료 이름으로 말하며 정답 토큰은 말하지 않는다. 남은 충돌 개수도 알리지 않는다.
- 2·4·6회 힌트(4.6)는 그대로다. 6회 자동 완성은 토큰과 근거를 함께 채운다.
- 퍼즐 "제공 정보"와 카드 설명에서 답의 근거가 되는 사실 요약(P01 info 4줄, P04 카드 detail, P05 부제)을 뺐다. 근거는 원문 자료 열기(4.6)로 읽는다. 정답 칸마다의 근거와 원문 문장은 `docs/퍼즐_근거표.md`(`tools/puzzle-evidence-table.ts`)에 있고, 그 표의 인용문·획득 시점은 테스트가 검사한다.
- `submitPuzzle` 에는 근거(`links`)를 반드시 넘긴다. 근거 없이 판정하는 호출 경로는 없다(테스트로 고정).

### 11.5 플레이 테스트 2차에서 기획서와 다르게 처리한 것
- **P01 이동 대상 근거 재설계:** 의자 끌린 자국을 E04(손목띠)·`mono_wristband` 에서 빼고, 원장실 의자(`director_chair`)를 조사 지점으로 만들었다. 조사하면 독백(`mono_chair`, voice inner)이 나오고 관찰 카드(`han_o_chair`, 화자 한지수)를 얻는다. 관찰 카드는 진술 카드와 같은 구조라 새 단서 ID(E번호)는 없다. P01 은 의자를 조사해야 열리고(`openWhen.flags: chair_checked`), 조사 전에는 의자 위에 반짝임이 보인다. 이동 대상 칸의 허용 근거는 이 관찰 카드와 E03(예비 기록의 위치와 공식 설명의 위치가 달라 원장이 옮겨졌음)이다. 기획서 P01 "제공 정보"의 "의자 다리의 끌린 자국"은 이 관찰로 대신한다.
- **걷기 애니메이션:** 모든 인물을 5프레임(걷기 2장 → idle_0 → 걷기 2장), 예전 fps 의 1/3(약 2.7fps)로 바꿨다. 순서·fps 는 `art/asset-spec.json` 의 `walk`(공통)와 `sequences[].walkCycle`(박은호는 보폭이 큰 walk_0·1·3·4)이다. 백선우의 걷기 그림(walk_0~3)은 pending 이고 들어오면 `import-generated --apply` 가 frames 에 더해 같은 규칙이 자동 적용된다.
- **맵 끝 검은 영역:** 계단이 있는 구역은 걸을 수 있는 범위(`walk`)를 계단·문 앞(가운데)까지로 하고, 벽·바닥 범위 밖은 카메라 여유 80px 만큼 검게 보인다(가장자리는 3단계 어두운 띠). 지난번 validate 규칙(끝의 빈 바닥 100px 이하)은 "걸을 수 있는 빈 바닥" 기준으로 바꿨다.
- **지하 철창문:** `stairs_b1` 은 잠겨 있을 때 닫힌 그림(`artLocked: stairs_basement_closed`, pending), 열린 뒤에는 `stairs_basement` 를 쓴다. 열리는 순간(`mono_basement_open`)과 열고 들어갈 때·잠김 시도에 `gate_clank` 가 난다.
- **대화 초상 방향:** 초상은 대화창 왼쪽에 있어 화면 안쪽(오른쪽)을 보게 한다. 원래 왼쪽을 보는 초상(한지수·박은호·정하늘)은 `characters.json` 의 `portraitFacing` 데이터로 좌우 반전한다. 원본 그림은 그대로다.
- **문 표시:** 사무실 문 이동 표시를 "[사무실] 나가기"로 맞추고, "나가기"가 들어간 표시의 행동 문구도 "나가기"로 한다.

### 11.6 걷기 속도와 발 맞춤
- (최종) 걷기 fps 6(5프레임 한 주기 0.83초, 발걸음 2번), 이동 속도 55px/s, 달리기 ×2(fps 12, 110px/s). 한 주기에 나아가는 거리 약 46px 는 새 걷기 그림의 걸음(접지 프레임에서 두 발 중심 간격 한지수 19~20px, 박은호 20px, 백선우 19~22px → 한 걸음 약 20~23px, 한 주기 약 40~46px)과 맞는다. 접지 프레임 사이 반 주기(0.42초)에 몸은 22.9px 가고 앞발이 뒤발 자리로 가는 거리는 19~22px 라 발이 미끄러지는 양은 한 걸음에 최대 3px(약 10%) 이다.
- (이전 기록) 처음에는 fps 5·65px/s 였다. 한지수 craft_on 그림은 걸음 하나가 약 28~32px 라 맞았지만, 11.9 에서 새 그림으로 바꾸며 걸음이 20px 쯤으로 줄어 발이 약 1.6배 미끄러졌다.
- Shift 달리기는 이동 속도(×2)와 걷기 fps(×2)를 함께 올린다. 발걸음 효과음 간격은 asset-spec 의 걷기 주기에서 자동으로 구한다(걸음 417ms, 달릴 때 208ms).
- 연출 속 이동(오프닝 박은호, 1층 첫 입장 플레이어·백선우)은 단계 데이터에 속도를 따로 쓰지 않고 같은 `playerSpeed` 를 쓴다. 느려진 만큼 오프닝 대기(0.8→0.2초, 1.2→0.2초), 박은호가 멈추는 자리(gap 56→72), 퇴장 도착점(540→460, 카메라 밖), 1층 첫 입장 대기(0.5→0.3초, 0.6→0.3초), 백선우 퇴장 거리(330→290)를 줄였다. 오프닝 전체는 약 24.0초 → 25.0초.
- 구역 끝에서 끝까지(`tools/walk-times.ts`): 사무실 10.4초(달리기 5.2), 1층 29.5초(14.7), 원장실 12.1초(6.0), 2층 24.5초(12.3), 병실 8.8~11.2초(4.4~5.6), 3층 17.2초(8.6), 부원장실·간호사실 8.8초(4.4), 이혜정실 10.4초(5.2), 지하 17.2초(8.6).

### 11.8 배치 7 일부 적용 (백선우 걷기 · 혈흔 v2)와 걷기 정규화 규칙
- 걷기 공통 순서는 `walk_0 → walk_1 → walk_pass → walk_2 → walk_3`(5fps). 한지수·박은호는 `_v2` 가 올 때까지 지금 그림을 유지하므로 인물별 `walkCycle`(가운데 idle_0)을 둔다. 5장(walk_0~3, walk_pass)이 모두 `_v2` 로 들어오면 `import-generated` 가 그 인물의 `walkCycle` 을 지워 공통 순서가 쓰인다.
- 정규화(`alignFeet: true` 인 시퀀스): 모든 프레임이 같은 배율(캔버스 전체 기준)이라 머리가 내려가는 프레임(walk_1·walk_3)도 몸 크기가 같다. 프레임마다 맨 아래 불투명 줄(발바닥)을 재서 캔버스 바닥선에 맞춘다(세로 이동만). 백선우: 대기·걷기 모두 발 하단 y=89, 몸 높이 84~88px(걸을 때 머리가 4px 내려간다).
- `_v2` 인식: manifest 의 `walk_0_v2.png` 는 같은 이름 `walk_0` 의 최신판이다(`frameSrc`). 생성 폴더를 쓰는 인물은 v1 도 쓰고, craft_on 그림을 쓰는 인물은 v2 이상만 바꿔 넣는다. 새로 들어온 인물은 `alignFeet` 가 켜진다.
- E02 상세 그림은 `ev_altar_blood_v2`(옛 `ev_altar_blood.png` 는 `illustExclude` 로 빼 용량을 늘리지 않는다).

### 11.9 한지수·박은호 걷기 교체 (배치 7 수정본)
- 한지수 `walk_0~3_v2` + `walk_pass_v2`, 박은호 `walk_0~3_v2` + `walk_pass_v3`(v2 는 몸이 커서 쓰지 않는다 — 같은 이름의 최신판 규칙으로 v3 가 선택된다)을 쓴다. 대기(idle_0·idle_1)는 craft_on 원본 그대로이고, 원본 사본(art/source/Art/…)은 건드리지 않는다. 인물별 `walkCycle` 은 없어지고 공통 순서 `walk_0 → walk_1 → walk_pass → walk_2 → walk_3` 을 쓴다.
- 새 걷기 그림(`frameSrc`)은 초록 배경을 지우고(`keyed0`) 이미 그림에 들어 있는 검은 외곽선을 그대로 쓴다(외곽선을 더하지 않는다). `alignFeet` 로 발 하단을 바닥선에 맞춘다.
- 크기 맞춤: 캔버스가 craft_on 210×360, 새 그림 672×1152(비율은 같다). 정규화 후 몸 높이 한지수 idle 86 / 걷기 85~86(차이 ≤1, 보정 없음), 박은호 idle 90 / 걷기 87·85 → 차이 3·5px 라 박은호 걷기만 `walkScale: 1.034`(새 걷기 그림에만, 위·옆을 잘라 캔버스 90 유지)로 맞췄다 → 걷기 90·88(머리가 내려가는 프레임 −2).
- 보폭: 접지 프레임(walk_0·walk_2)의 두 발 중심 간격 한지수 19~20px, 박은호 20px, 백선우 19~22px → 한 주기(걸음 2번)에 그림이 나아가는 거리 약 40px 인데 이동은 65px/주기라 발이 미끄러진다(약 1.6배). 이동 속도·fps 는 이번에는 그대로 둔다. 맞추려면 이동 속도를 약 42px/s 로 낮추거나 걷기 fps 를 8(달리기 16)로 올린다.

### 11.10 플레이 테스트 3차 반영 (퍼즐·최종 보고서·교단 설정은 다음 작업)
- 새 문장은 모두 `source: "new"`, 생각·행동은 `voice`, 이름은 `{player}` 토큰이다. 새 단서 ID·퍼즐·인물은 없다.
- **오프닝 인사:** 박은호가 노크 → 입장 뒤 인사·소개(`n0a~n0c`: "실례합니다. {player} 탐정님 사무실…맞죠?" / "네, 앉으세요." / "박은호라고 합니다. 동생 일로 왔어요.")를 한 뒤 기존 본론으로 간다.
- **대화 시작을 플레이어의 질문으로:** 최옥자·한유진·채소연·오미란·백선우(부원장실)·이혜정 대화는 플레이어의 짧은 질문 한 줄(`c0·y0·s0·o0·k0·l0`)로 시작한다. 정하늘(`h1`)은 원래 플레이어가 먼저 말한다.
- **다시 말 걸기:** 완료만 표시하던 `restart`(`choi_done`·`han_done`·`chae_done`·`oh_done`·`baek_done`·`lee_done`)는 없앴다 — 같은 대화는 처음부터 다시 재생한다. 상태가 바뀌어야 달라지는 `restart`(오미란 인정 후, 백선우 거부·E07, 이혜정 거부·E11, 정하늘 추궁)는 그대로 두고, 그 상태에서 이미 끝까지 본 대화(`dlgdone:<대화>:<시작 노드>` 플래그)에는 새로 바뀐 것이 없으므로 처음부터 다시 재생한다(`openingNodeOf`).
- **대사 기록(백로그):** 지금 구역에서 본 대사를 다시 읽는다. 탐색 중에는 L 키, 대화 중에는 L 키 또는 대화창 오른쪽 위 `[L] 기록` 버튼. 구역별 최근 200줄을 메모리에만 두고 저장하지 않는다(이어하기 뒤에는 새로 쌓인다). 조작법 화면·README·상단 안내에 L 을 넣었다.
- **정하늘(지하):** 회상 대사의 "침대에 보내겠다"를 "특별 치료로 보내겠다"로, "제 손이 없어지는 건 아니니까"를 "제가 한 일이 없던 일이 되는 건 아니라는 거"로 고쳤다. 질문 세 개를 모두 물어야 [계속]이 뜨던 구조는 없앴다: 대사 노드에 `nextIf: [{flags, next}]`(효과 적용 뒤 조건이 맞으면 `next` 대신 그 노드로)를 넣어, 세 번째 대답이 끝나면 자연스럽게 다음 대사로 이어진다. 묻지 않은 질문이 남았으면 질문 목록으로 돌아간다.
- **박은호 메시지(`voice: "message"`):** 휴대폰 메시지 틀과 회상 띠 중 **회상 띠**로 정했다. 대화창이 112px 높이라 휴대폰 틀(세로 비율)은 글이 들어갈 자리가 모자라고, 선택지가 바로 이어지는 장면이라 틀 안에 갇히면 읽기 불편하다. 띠는 대화창 자리를 그대로 쓰되 바탕·윗선을 푸른 회색으로 바꾸고, 머리말을 "✉ 박은호의 메시지"로, 초상은 없애고, 본문은 괄호 없이 왼쪽 선과 함께 보여 준다. 대사 기록에도 같은 머리말로 남는다. 바로 이어지는 "A를 고르면…" 선택 문장(플레이어의 생각)은 기존 inner 그대로다.

### 11.12 퍼즐 구조·판정 개편 (사용자 결정 2026-11-12): 결론 기회 3번 · 조각 = 단서 문장
- 11.3(근거 카드 규칙)은 폐기한다. 근거 카드 붙이기 UI(`evidenceLinks`, [근거 붙이기])를 없앴고, 퍼즐 조각 자체가 단서의 핵심 문장(인용)이다. 조각(`puzzles.json` 의 `tokens`)마다 출처(단서·진술 ID, 대화 독백은 `dialogue:<대화>:<노드>` + `srcName`)가 있고, 가진 자료의 조각만 나타난다(`availablePieces`). 오답 조각(`decoy`)은 어느 칸에도 놓지 않는 것이 정답이고, 오답 위치(문 앞·창가)나 칸 밖에 놓은 조각이 있으면 오답이다.
- **결론 기회 3번**(`src/core/puzzle.ts`): [결론 확정] → 확인 창("이 결론을 확정할까요? 남은 기회 N/3") → 판정. 모든 칸이 채워지지 않으면 확정할 수 없고 기회는 줄지 않는다. 1번째 오답 = 충돌 문장 하나 + 힌트 문장, 2번째 오답 = 충돌 문장 하나 + 틀린 후보 하나 제거, 3번째 오답 = 검증 실패(퍼즐이 닫혀 다시 열 수 없다, `failedPuzzleIds`·`puzzle_failed:<ID>`). 칸을 자동으로 채우는 힌트와 6회 단계는 없앴다(`hintTexts` 는 2개). 충돌 문장은 조각의 출처 이름으로 말한다("「백선우의 진술」은(는) 이 위치와 맞지 않는다.").
