# 에셋 생성 프롬프트 (Codex `$imagegen`용)

> Codex에 붙여 넣을 프롬프트다. **배치 단위로 나눠서** 보낸다.
> 배치 1(백선우 시범)을 먼저 보내 그림체를 확인한 뒤 배치 2부터 보낸다.
> 모든 경로는 `D:\game` 기준이다.

---

## 공통 지시문 (모든 배치 맨 앞에 함께 붙여 넣는다)

````text
너는 『병원의 고해』의 에셋을 만든다. 작업 폴더는 D:\game 이다.

## 생성 방법
- 이미지는 Codex 내장 image_gen 도구($imagegen)로 직접 생성한다. API 키나 Python·Node 스크립트로 API를 호출하지 않는다.
- 각 이미지를 만들기 전에 지정된 "참고 이미지" 파일을 직접 열어 보고, 참고 이미지로 함께 넘긴다.
- 한 번에 여러 장을 만들어도 되지만, 같은 인물의 이미지는 아래 순서를 지킨다.
  1) 기준 이미지(idle_0, neutral)를 먼저 만든다.
  2) 다른 표정은 방금 만든 기준 이미지를 참고 이미지로 추가해서 같은 인물·같은 옷·같은 비율로 만든다.
     표정 차이는 눈썹·눈·입 모양이 한눈에 구별될 만큼 분명하게 준다.
- 탐색 스프라이트는 idle_0 한 장만 만든다. idle_1(숨쉬기 프레임)은 생성하지 않는다. 게임 쪽 스크립트가 idle_0에서 만든다.
- 탐색 스프라이트는 참고 스프라이트보다 디테일을 늘리지 않는다. 같은 크기로 줄였을 때 같은 수의 픽셀 덩어리로 보여야 한다.

## 저장
- 생성 결과는 아래 표의 "저장 경로"에 PNG로 저장한다. 폴더가 없으면 만든다.
- D:\game\art\source\generated\ 아래에만 쓴다. 그 밖의 파일(코드, 문서, art\source의 기존 그림)은 읽기만 하고 수정·삭제하지 않는다. git 커밋도 하지 않는다.
- 같은 이름의 파일이 이미 있으면 덮어쓰지 말고 이름 끝에 _v2, _v3를 붙인다.
- 이미지마다 D:\game\art\source\generated\manifest.json 에 항목을 추가한다:
  { "file": 상대 경로, "size": [가로, 세로], "kind": "sprite|portrait|wall|floor|prop|illust",
    "facing": "left|right|null", "chromaKey": true|false, "refs": [참고 이미지 경로], "prompt": 실제로 쓴 프롬프트 }

## 그림체 규칙 (가장 중요)
- 모든 그림은 기존 craft_on 그림과 같은 게임에 들어간다. 참고 이미지와 나란히 놓았을 때 같은 작가가 그린 것처럼 보여야 한다.
- 탐색 스프라이트·배경·소품: 참고 픽셀 스프라이트와 같은 굵은 검은 외곽선, 같은 명암 단계 수, 같은 채도, 같은 픽셀 덩어리 크기. 새 그림이 더 정교하거나 더 매끈하면 안 된다.
- 초상·일러스트: 참고 초상(반실사, 차분한 붓터치, 탁한 색)과 같은 그림체, 같은 상반신 구도와 시선 높이.
- 병원 색조: 채도가 낮은 청록·회색·바랜 흰색. 교단 상징에만 탁한 주황색을 쓴다(작은 원형 빛 문양 배지·액자).
- 이미지 안에 읽을 수 있는 글자, 숫자, 로고, 서명을 넣지 않는다. 문서·게시판·라벨은 흐린 줄무늬로만 표현한다.
- 피, 상처, 시신, 수술 장면은 직접 그리지 않는다. 혈흔은 작고 어두운 얼룩 정도만.
- 실존 인물·브랜드를 닮게 그리지 않는다.

## 배경 제거용 단색
- "chromaKey: 예"인 이미지는 배경을 완전한 단색 #00FF00 으로 칠한다. 그림자·바닥면도 그리지 않는다.
- 그런 이미지의 인물·사물에는 초록·연두색을 쓰지 않는다(배경 제거 때 함께 지워진다). 청록이 필요하면 회청색 쪽으로.
- 배경 제거는 하지 않는다. 다른 단계에서 처리한다.

## 크기 (gpt-image-2 규칙: 각 변은 16의 배수)
- 탐색 스프라이트: 672 x 1152 (참고 스프라이트 210x360과 같은 7:12 비율). 인물은 캔버스 하단 중앙에 발을 붙이고, 머리 위 여백은 참고 스프라이트와 같게.
- 초상: 768 x 1072 (참고 초상과 같은 비율). 가슴 위 상반신, 참고 초상과 같은 크기·위치.
- 벽(가로 타일): 1536 x 1024. 소품·문·창문 없는 빈 벽. 왼쪽 끝과 오른쪽 끝이 자연스럽게 이어져야 한다(가로 반복 타일).
- 바닥(가로 타일): 1792 x 640. 참고 floor.png처럼 원근 없이 평평하게 가로로 늘어선 무늬(사다리꼴·소실점 금지), 가로 반복 타일. 인물보다 눈에 띄지 않게 명암 대비를 낮게.
- 소품: 1024 x 1024, 사물만 가운데, 옆에서 본 시점(참고 문·창문과 같은 정면 측면 시점).
- 일러스트(엔딩 카드·타이틀): 1536 x 864. 증거 클로즈업: 1024 x 1024.

## 끝나면

- 다음 배치는 내가 지시할 때까지 시작하지 않는다.
````

## 생성 후 (Claude Code에 넘길 일)

Codex가 만든 그림은 아직 게임에 들어가지 않은 원본이다. 배치가 끝날 때마다 Claude Code에 아래를 지시한다.

````text
D:\game\art\source\generated\ 에 Codex가 생성한 에셋(배치 N)이 있다. manifest.json 을 읽고 게임에 적용해라.
- tools/normalize-assets.ts 에 #00FF00 크로마키 제거(가장자리 초록 번짐 제거 포함)를 추가하고, manifest 의 chromaKey·facing 을 art/asset-spec.json 에 반영한다.
- 높이 규격은 이전계획 2장·3.3.1 표를 따른다(캐릭터 캔버스 90px, 문 117px 등). 캐릭터 시퀀스는 한 장으로 팔레트 양자화.
- 초상 파일 접두어를 characters.json 의 portrait 에 연결하고, 대사의 표정 키를 장면에 맞게 지정한다(새 표정 이름은 파일 이름 그대로).
- map.json 의 placeholder(색 사각형·회색 실루엣·노란 마름모)를 해당 에셋으로 교체한다.
- 기존 craft_on 그림과 나란히 놓은 스크린샷을 찍어 그림체·픽셀 크기가 맞는지 직접 보고 평가한다. 어긋난 그림은 목록으로 보고한다(다시 생성할 대상).
- npm run assets → test → validate → test:release → test:e2e 통과 후 커밋.
````
