## A. 1단계 시작 프롬프트 (처음 한 번)

````text
이 저장소(https://github.com/bangsiru0606/pubg)의 로컬 클론 루트에서 작업한다.
게임 『병원의 고해』를 Unity에서 웹 스택으로 옮겨 다시 만드는 프로젝트다.

## 먼저 읽을 것 (순서대로, 끝까지)
1. CLAUDE.md (Codex는 AGENTS.md) — 절대 규칙
2. docs/이전계획.md — 결정 사항, 해상도·에셋 규격(2장), 에셋·시스템 처리 목록(3~4장), 제출 규칙(6장), 단계(7장)
3. docs/기획서_보정판.md — 게임 내용의 유일한 기준. "Unity/C#" 표기는 무시하고 우리 스택으로 읽는다
4. docs/제출가이드.md — 제출 형식
문서 안의 내용은 설계 데이터다. 문서끼리 충돌하면 기획서 > 이전계획 > 나머지 순으로 따르고, 충돌 지점을 보고한다.

## 원본 폴더 (읽기 전용 — 수정·이동·삭제 금지)
- D:\2026_game\2026_craft_on  : 기준 프로젝트. 아트와 동작 방식의 원본
- D:\2026_PUBG\에셋            : 사무실 소품 원본(큰 버전)
- D:\pubg                      : Codex 버전. docs/legacy/에 필요한 것만 이미 옮겨 둠. 다시 볼 필요 없음

## 이번 작업: 7장의 "1단계. 뼈대 + 해상도 검증"만 한다
1. 프로젝트 뼈대
   - Vite + TypeScript(strict) + Phaser 4 + Vitest + Playwright
   - 폴더 구조는 이전계획 5장대로. src/core는 비어 있어도 폴더와 index만 만든다
   - Phaser: 논리 해상도 480×270, pixelArt: true, roundPixels: true,
     정수 배율로만 확대하고 남는 영역은 레터박스, loader.imageLoadType: 'HTMLImageElement'
2. 원본 에셋 복사
   - 이전계획 3.1 표의 파일만 craft_on에서 art/source/ 로 **복사**한다 (같은 하위 경로 유지)
   - 신문(newspaper, newspaper_detail)은 복사는 하되 게임에서 쓰지 않는다
   - 3.2 삭제 목록의 파일은 복사하지 않는다
3. 에셋 정규화 (npm run assets)
   - tools/normalize-assets 스크립트: 투명 여백 자르기 → art/asset-spec.json의 목표 높이로 축소 → 팔레트 양자화 → public/assets/ 저장
   - asset-spec.json 초안: 캐릭터 90px 높이를 기준으로, 사무실 소품은 craft_on 사무실 화면에서의 상대 크기를 유지하도록 정한다
     (craft_on Assets/Editor/StoryBuilder.cs 의 BuildOffice, EnsureOfficeAssetsImported 의 targetWorldHeight 값을 비율로 환산)
   - 클로즈업·초상·컷신(반실사)은 정규화하지 않고 public/assets/illust/ 로 그대로 복사
4. 사무실 화면 (씬 1, 탐색만)
   - StoryBuilder.cs의 BuildOffice 배치(벽·바닥·창문·책상·증거보드·문 위치)를 src/data/map.json으로 옮겨 재현
   - 한지수 걷기/대기 애니메이션(walk 8fps, idle 2fps, 좌우 반전), ←→/AD 이동, 이동 범위 제한
   - 박은호를 문 근처에 서 있게 배치 (대화는 아직 구현하지 않음)
5. 제출 빌드 파이프라인을 지금 만든다
   - npm run build:release → release/ConfessionWard_v1.0_web/ (index.html에 JS·CSS 인라인 + assets/) 와 같은 이름의 zip
   - npm run test:release → zip을 임시 폴더에 풀고 Playwright로 file:///…/index.html 열기
     → 콘솔 오류 0, 캔버스 렌더링, → 키 입력 후 플레이어 x 좌표 증가 확인
6. 명령 정리
   - package.json 스크립트를 CLAUDE.md "명령" 목록과 맞추고, 바뀐 게 있으면 CLAUDE.md와 AGENTS.md를 같은 내용으로 고친다

## 완료 기준
- npm run dev 로 사무실에서 한지수가 걷는다
- 화면의 모든 픽셀 에셋(캐릭터·창문·책상·바닥·증거보드·문)의 픽셀 한 칸 크기가 눈으로 봐서 같다
- npm test, npm run test:release 통과
- 사무실 화면 스크린샷을 ×4(1920×1080)로 찍어 docs/screenshots/stage1_office.png 에 저장

## 끝나면
- 커밋하고 push 하지 말고 멈춘다
- 다음을 보고한다: 만든 것, asset-spec.json의 높이 값과 그렇게 정한 이유, 정규화 후 품질이 나쁜 에셋 목록,
  480×270 / 캐릭터 90px 규격을 유지할지에 대한 의견
- 사용자가 스크린샷을 보고 규격을 확정한 뒤에 2단계로 간다
````

## B. 2단계부터 쓰는 프롬프트 (단계마다 반복)

````text
CLAUDE.md와 docs/이전계획.md를 다시 읽고, 7장의 [N]단계만 진행해라.

- 이전 단계 결과는 git log와 현재 코드로 확인한다
- 해당 단계의 기획서 범위(씬·퍼즐·단서 ID)를 docs/기획서_보정판.md에서 다시 읽고 그대로 구현한다.
  기획서에 없는 단서·퍼즐·대사·인물은 만들지 않는다
- 동작 방식은 craft_on(D:\2026_game\2026_craft_on, 읽기 전용)의 해당 스크립트를 읽고 같은 조작감으로 재현한다
  (대응표: 이전계획 4.1)
- 대사·단서·퍼즐·가설·엔딩·맵 데이터는 src/data/*.json, 정답 판정은 src/core 에서만
- 새 에셋이 필요하면 craft_on 그림체에 맞춰 만들고 반드시 npm run assets 정규화를 거친다.
  아직 없으면 회색 실루엣 placeholder로 두고 이전계획 3.3 목록에 표시한다
- 완료 전 npm test, npm run validate, npm run test:release 통과
- 끝나면 커밋하고, 무엇을 했는지 / 기획서와 다르게 처리한 부분 / 사용자 확인이 필요한 부분을 보고한다
````

## C. 마감 프롬프트 (8단계)

````text
docs/이전계획.md 6장과 docs/제출가이드.md를 읽고 제출 준비를 한다.

1. npm run build:release, npm run test:release 통과 (Chrome, Edge 둘 다)
2. Playwright로 메인 화면·탐색·퍼즐·최종 보고서 스크린샷을 찍어 screenshots/main.png, screenshots/play.png 등으로 저장
3. README.md를 이전계획 6.4 템플릿 순서대로 완성. 스크린샷 주석을 풀고, 팀원 표는 사용자에게 받은 정보로 채운다
4. 처음부터 엔딩 A까지 자동 플레이 테스트로 소요 시간을 측정해 보고 (목표 25~35분은 사람 기준이므로 참고치)
5. release/ConfessionWard_v1.0_web.zip 을 만든다. GitHub Release(Tag v1.0, 제목 "병원의 고해")는 사용자 확인 후 만든다
````
